# rag-mcp

[![CI](https://github.com/ZizzX/rag-mcp/actions/workflows/ci.yml/badge.svg)](https://github.com/ZizzX/rag-mcp/actions/workflows/ci.yml)

Локальный RAG по вашим Markdown и PDF, доступный любому агенту через MCP
(Claude Code, Claude Desktop, Cursor). Гибридный поиск: векторный (numpy, по желанию Qdrant) +
BM25, слияние через RRF. Эмбеддинги через Ollama по умолчанию, без облака.

Работает на Windows, macOS и Linux. Один и тот же репозиторий на всех машинах,
установка одной командой.

## Быстрый старт

```bash
git clone https://github.com/ZizzX/rag-mcp.git && cd rag-mcp
./install.sh          # macOS / Linux
.\install.ps1         # Windows (PowerShell)
```

Установщик ставит `uv` (он сам скачает нужный Python), зависимости из
`uv.lock`, создаёт `.env`, тянет модель эмбеддингов в Ollama и через
`rag-mcp register` подключает сервер к Claude Code, Cursor и Claude Desktop
(спрашивает про каждый найденный клиент; `--yes` / `-Yes` без вопросов,
`--no-claude` / `-NoClaude` пропустить). Повторный запуск безопасен: после
`git pull` просто запустите его ещё раз.

Дальше:

```bash
uv run rag-mcp ingest                     # проиндексировать data/docs (инкрементально)
uv run rag-mcp search "как откатить деплой"
uv run rag-mcp status
```

В Claude Code наберите `/mcp`: сервер `rag-mcp` должен быть в списке. После
этого просто задавайте вопросы по документам, Claude сам вызовет `search`:
`register` ставит ему скилл с правилом, когда искать в заметках раньше grep
(см. [Подключение к агентам](#подключение-к-агентам)).

### Установка на новом устройстве (пошагово, в том числе для агента)

1. Установить [Ollama](https://ollama.com) и запустить её. Установщик Ollama
   не ставит, без неё работает только BM25-поиск.
2. `git clone https://github.com/ZizzX/rag-mcp.git && cd rag-mcp`, затем
   `./install.sh` (Windows: `.\install.ps1`). Он создаст `.env` из
   `.env.example`, скачает модель эмбеддингов и зарегистрирует сервер в
   найденных клиентах (`rag-mcp register`: Claude Code на уровне пользователя,
   Cursor, Claude Desktop) вместе со скиллом для агента.
3. Подключить папки с документами: `uv run rag-mcp add /путь/к/заметкам --name notes`
   (по одной команде на папку; имя станет префиксом `notes/` в результатах).
   Документы можно и положить в `data/docs` или указать `RAG_DOCS_DIR`, тогда
   `uv run rag-mcp ingest`.
4. Проверить: `uv run rag-mcp status` (эмбеддер, число чанков),
   `uv run rag-mcp projects`, `uv run rag-mcp search "вопрос по документам"`,
   `claude mcp get rag-mcp` → `Connected`.
5. Перезапустить открытые сессии Claude Code: сервер виден только в новых.

Индекс и подключённые проекты локальны для машины, на другое устройство не
переносятся: на каждом повторите шаг 3. Сменили модель эмбеддингов в `.env`:
`uv run rag-mcp ingest --rebuild`, иначе поиск ответит ошибкой о размерности
векторов.

## Требования

- [Ollama](https://ollama.com) запущен (для эмбеддингов). Модель по умолчанию
  `bge-m3` (многоязычная, ~1.2 ГБ, `ollama pull bge-m3`); установщик скачивает её
  сам. На русских заметках она находит заметно лучше `nomic-embed-text`. Кому
  нужна модель полегче: `RAG_EMBED_MODEL=nomic-embed-text` в `.env`.
  Сменили модель (в том числе обновились с версии, где по умолчанию был
  `nomic-embed-text`): `uv run rag-mcp ingest --rebuild`.
- Docker Desktop не обязателен. Индекс по умолчанию это обычные файлы в
  `data/index` (`manifest.json`, `bm25.json`, `vectors.npy`), векторный поиск
  полным перебором через numpy. Индекс одновременно читают сколько угодно
  процессов: каждая сессия Claude Code, Claude Desktop или Cursor запускает свой
  `rag-mcp serve`, и все они работают, в том числе пока идёт `ingest`. Пишет
  один процесс за раз (блокировка `index.lock` только на время записи).
- Сервер Qdrant нужен только для очень больших корпусов (сотни тысяч чанков):
  `docker compose up -d` и `RAG_QDRANT_URL=http://localhost:6333`.

## Команды

| Команда | Что делает |
|---|---|
| `rag-mcp ingest [--rebuild]` | индексирует новые и изменённые файлы, удаляет пропавшие; `--rebuild` пересоздаёт индекс (нужно после смены модели эмбеддингов) |
| `rag-mcp search "вопрос" [-k N] [--project NAME] [--source PREFIX ...] [--json]` | поиск из терминала |
| `rag-mcp serve` | MCP-сервер по stdio (его запускает Claude Code) |
| `rag-mcp status` | где документы и индекс, какой эмбеддер, сколько чанков |
| `rag-mcp add [ПАПКА] [--name ИМЯ] [--force]` | подключить папку проекта: её документы индексируются на месте, без копирования; без пути берётся git-репозиторий вокруг текущей папки |
| `rag-mcp remove ИМЯ` | отключить проект и убрать его документы из индекса (файлы на диске не трогает) |
| `rag-mcp projects` | подключённые проекты и папки проектов внутри `RAG_DOCS_DIR`; текущий проект помечен |
| `rag-mcp eval [eval/questions.jsonl] [-k N]` | hit-rate и MRR по золотому набору вопросов |
| `rag-mcp register [--claude-code] [--cursor] [--claude-desktop] [--all] [-y] [--no-rules] [--dry-run] [--force] [--allow-worktree]` | подключить сервер к агентам и поставить скилл; см. [Подключение к агентам](#подключение-к-агентам) |
| `rag-mcp unregister [--claude-code] [--cursor] [--claude-desktop] [--all] [-y] [--dry-run]` | убрать всё, что поставил `register` |

Инструменты MCP: `search` (параметры `project`, `source_prefix`, `all_projects`), `fetch_document`, `list_sources`, `index_status`, `reindex` (инкрементальный ingest, `rebuild=true` для полной пересборки).

Индекс обновляется сам: при старте сервер в фоне индексирует файлы, добавленные,
изменённые или удалённые с прошлого ingest. Добавили документ во время работы:
попросите агента вызвать `reindex` или выполните `rag-mcp ingest`, остальные
серверы подхватят изменения при следующем запросе. Если Ollama не запущена,
`search` всё равно отвечает: ищет только по BM25 и пишет в поле `degraded`,
почему векторов нет и как их вернуть. Если индекс пуст или сменилась модель
эмбеддингов, инструменты возвращают текст с тем, что сделать, а не
«Error executing tool».

## Конфигурация

Все настройки в `.env` (см. `.env.example`), префикс `RAG_`. Пути относительные
к корню проекта, поэтому сервер работает из любой директории.

## Несколько проектов

Один сервер обслуживает все проекты. Документы раскладываются по подпапкам,
имя подпапки равно имени папки проекта на диске, общие документы в `common/`:

```
rag-docs/
  common/            правила, шаблоны, документы для всех проектов
  shop-backend/      документы только этого проекта
  mobile-app/
  notes.md           файлы в корне видны всегда
```

При каждом вызове `search` сервер определяет, в каком проекте открыт Claude Code,
и ищет только в его папке и в `common/`. Ничего прописывать в `CLAUDE.md`
проектов не нужно. Источник определения, по убыванию надёжности:

1. Корни рабочей области (MCP roots): Claude Code сообщает папку, в которой
   запущена сессия. Подпапка проекта тоже распознаётся, сервер поднимается
   вверх по дереву до совпадения с проиндексированной папкой.
2. Переменная `CLAUDE_PROJECT_DIR`, которую Claude Code выставляет серверу.
3. Рабочая директория процесса сервера.

Если совпадения нет, ищет по всем проектам и говорит об этом в ответе
(`scope.mode = "all"`). Переопределить можно параметрами инструмента:
`project="mobile-app"`, `all_projects=true` или `source_prefix="common/"`.
Список общих папок задаётся `RAG_SHARED_PROJECTS` (по умолчанию `common`),
принудительный проект `RAG_PROJECT`.

Из терминала: `uv run rag-mcp search "вопрос" --project shop-backend`.

### Подключить папку проекта без копирования

Документы проекта не обязательно класть в `RAG_DOCS_DIR`. Команда
`uv run rag-mcp add` в папке репозитория (или `add /путь --name имя`) подключает
папку на месте: файлы индексируются там, где лежат, в результатах у них префикс
`имя/`. Проект определяется по пути, git origin, `.git` или имени папки, так что
поиск из этой папки сам ограничится её документами. Список: `rag-mcp projects`,
отключить: `rag-mcp remove имя`. Домашнюю папку и папки больше 5000 документов
подключить можно только с `--force`.

Что сюда не стоит класть: правила работы и соглашения по коду. Они должны лежать
в `~/.claude/CLAUDE.md` и в `CLAUDE.md` проекта, эти файлы Claude читает всегда,
а из rag-mcp достаёт только то, что решил поискать.

## Документы: как переиспользовать на нескольких устройствах

Репозиторий содержит только код и установщик. Документы и индекс в git не
попадают (`data/docs`, `data/index` в `.gitignore`). Варианты синхронизации
документов между машинами, от простого к сложному:

1. **Синхронизируемая папка.** Dropbox, OneDrive, iCloud, Syncthing. В `.env`
   укажите `RAG_DOCS_DIR=/path/to/synced/folder`. Ничего больше не нужно.
2. **Отдельный приватный репозиторий `rag-docs`.** Клонируйте его в
   `data/docs` (или куда угодно и укажите `RAG_DOCS_DIR`). Код публичный,
   документы приватные, история правок есть у обоих.
3. **Один репозиторий, документы как git submodule** в `data/docs`. Удобно,
   если хочется клонировать всё одной командой, но submodule добавляет
   трения при обновлениях.

Индекс всегда локальный: он привязан к модели эмбеддингов и занимает место.
После клонирования на новой машине выполните `uv run rag-mcp ingest`, это
занимает минуты даже для тысяч страниц.

### Делить ли на несколько репозиториев

Код для Windows, macOS и Linux одинаковый, различаются только установщики
(`install.sh` и `install.ps1`), поэтому делить код по платформам не нужно.
Разумная граница одна: **код** (этот репозиторий) и **данные** (документы,
вариант 1 или 2 выше). Если позже появятся сильно разные пайплайны, например
отдельный для кода и отдельный для документов, их проще держать как разные
конфиги `.env` и разные коллекции (`RAG_COLLECTION`), а не как разные репозитории.

## Подключение к агентам

Одного MCP-сервера мало: агент не знает, что в заметках есть решения и планы
прошлых сессий, и ищет grep'ом. `rag-mcp register` подключает сервер и ставит
агенту правило, когда искать через `search` раньше grep и когда вызывать
`reindex`.

```bash
uv run rag-mcp register                 # спросит про каждый найденный клиент
uv run rag-mcp register --yes           # все найденные без вопросов (без терминала так же)
uv run rag-mcp register --cursor        # только названные клиенты; --all — все три
uv run rag-mcp register --dry-run       # показать, что изменится, ничего не писать
uv run rag-mcp unregister               # убрать всё, что поставил register
```

| Клиент | Найден, если | Что ставится |
|---|---|---|
| Claude Code | `claude` в PATH или есть `~/.claude` | сервер на уровне пользователя (`claude mcp add -s user`); скилл `~/.claude/skills/rag-mcp/SKILL.md`; блок из двух строк в `~/.claude/CLAUDE.md` |
| Cursor | есть `~/.cursor` | `mcpServers["rag-mcp"]` в `~/.cursor/mcp.json`; тот же скилл в `~/.cursor/skills/rag-mcp/SKILL.md` |
| Claude Desktop | есть папка его конфига | `mcpServers["rag-mcp"]` в `claude_desktop_config.json` (macOS: `~/Library/Application Support/Claude/`, Windows: `%APPDATA%\Claude\`, Linux: `~/.config/Claude/`); скиллы Desktop ставятся через его интерфейс, правило он получает из инструкций сервера |

Скилл говорит агенту: решения, чекпоинты, планы и ретро прошлых сессий, заметки
по подключённым проектам сначала искать через `search`, а grep оставить для
текущего кода; если ничего не нашлось, повторить с `all_projects=true`; при
`degraded` пустой ответ ничего не доказывает; после новых или изменённых
заметок вызвать `reindex`. `--no-rules` ставит только сервер.

Повторный запуск ничего не дублирует:

- файл пишется, только если меняется содержимое;
- в JSON-конфигах меняется только `mcpServers["rag-mcp"]`, остальные серверы и
  ваш `env` у записи `rag-mcp` сохраняются, перед записью делается бэкап
  `<файл>.bak-<дата>`; невалидный JSON не перезаписывается;
- блок в `CLAUDE.md` стоит между маркерами `<!-- rag-mcp:begin … -->` и
  `<!-- rag-mcp:end -->` и заменяется на месте, остальной файл не трогается;
- `SKILL.md`, написанный не `register` (без его пометки), не перезаписывается и
  не удаляется без `--force`;
- уже зарегистрированный в Claude Code сервер этой копии репозитория
  остаётся как есть, вместе с вашими `-e RAG_...`; `--force` переподключит.

Сервер запускается командой `<абсолютный путь к uv> --directory <эта папка> run
rag-mcp serve`: GUI-приложения не видят PATH терминала. Запускайте `register`
из той копии репозитория, которую должны использовать клиенты. Из git worktree
команда отказывается и подсказывает путь к основной копии: worktree временная,
и клиенты сломались бы после её удаления (`--allow-worktree`, если так и надо). После
регистрации перезапустите клиенты или откройте новую сессию.

### Ручная регистрация MCP

Claude Desktop (`claude_desktop_config.json`) или Cursor:

```json
{
  "mcpServers": {
    "rag-mcp": {
      "command": "uv",
      "args": ["--directory", "/absolute/path/to/rag-mcp", "run", "rag-mcp", "serve"]
    }
  }
}
```

На Windows путь вида `C:\\Users\\you\\rag-mcp`.

## Разработка

CI (GitHub Actions) гоняет тесты, установщики и офлайн-прогон CLI и MCP-сервера
на Ubuntu, macOS и Windows при каждом пуше в `main` и в pull request.

```bash
uv sync --extra dev
uv run pytest
RAG_EMBED_PROVIDER=hash RAG_DOCS_DIR=examples/docs uv run rag-mcp ingest   # офлайн-прогон без Ollama
```

Структура:

```
src/rag_mcp/
  config.py     настройки (.env, префикс RAG_)
  loaders.py    Markdown и PDF (PyMuPDF) -> Document
  chunking.py   разбиение по заголовкам, затем окна с перекрытием
  embeddings.py Ollama / OpenAI-совместимый API / hash (тесты)
  store.py      векторы (vectors.npy или сервер Qdrant) + BM25 + RRF
  pipeline.py   инкрементальный ингест и поиск
  server.py     MCP-сервер (stdio)
  evaluate.py   hit-rate и MRR по eval/questions.jsonl
  register.py   register / unregister: конфиги клиентов, скилл, блок CLAUDE.md
  cli.py        команды
```
