## Goal

Ручной `ingest` нужен только один раз. Дальше индекс обновляется сам: сервер (или
отдельная команда `rag-mcp watch`) следит за `docs_dir` и инкрементально
переиндексирует добавленные, изменённые и удалённые файлы. Поиск продолжает
отвечать во время переиндексации. Временные файлы редакторов и синхронизаторов
(`~$…`, `.swp`, `.tmp`, скрытые) игнорируются, серия быстрых сохранений
схлопывается в один прогон.

## Understanding

Прототип уже есть в ветке `feat/watch-mode` (CI зелёный на трёх ОС), но он сделан
поверх встроенного Qdrant и дублирует часть PR #2: инструмент `reindex` и
догоняющий ingest при старте. После мёржа #2 задача сводится к переносу
уникальной части поверх нового файлового хранилища:

- `src/rag_mcp/watcher.py` (watchfiles, debounce `RAG_WATCH_DEBOUNCE_MS`, фильтр
  `is_relevant`, `DocsWatcher` в daemon-потоке);
- `rag-mcp serve` запускает наблюдатель по умолчанию (`RAG_WATCH`, `--no-watch`),
  вместо своего startup-ingest использует `startup_ingest`/`reindex` из #2;
- `rag-mcp watch` как отдельная команда, когда сервер не запущен;
- `index_status.watch`: включён ли, число прогонов, последняя ошибка;
- запись идёт через `Pipeline.ingest` из #2, то есть под `index.lock`; если лок
  занят другим писателем, наблюдатель логирует и повторяет на следующем событии;
- тесты: фильтр, живой тест добавления/удаления файла, игнор временных файлов.

Мой `reindex`, мой startup-ingest и RLock вокруг search/ingest из прототипа
выбрасываются: в #2 это решено иначе (отдельный store-объект для записи,
перечитывание по mtime манифеста).
