## Goal

Косвенные и разговорные вопросы («а сколько у нас отпуск?») часто не совпадают
лексически с текстом документа. Локальная модель формулирует 2-3 варианта
запроса (синонимы, формальная формулировка, ключевые слова), поиск идёт по
всем, результаты сливаются RRF. Включается настройкой, по умолчанию выключено.

## Understanding

- `RAG_QUERY_REWRITE=true`, модель `RAG_LLM_MODEL` (Ollama chat, например
  qwen2.5:7b или llama3.1:8b), промпт просит N вариантов строкой на каждый,
  язык вариантов = язык вопроса. Таймаут и фолбэк на исходный запрос при любой
  ошибке: переписывание не должно ломать поиск.
- Исходный запрос всегда участвует в слиянии и получает небольшой бонус веса.
- Кэш переписываний (dict в памяти сервера + опционально файл), чтобы повтор
  вопроса не ходил в модель.
- Опционально HyDE: модель пишет гипотетический абзац-ответ, его эмбеддинг
  используется как ещё один dense-запрос. Делать вторым шагом, только если
  eval показывает прирост.
- Трасса (T-006) должна показывать, какие варианты сгенерированы и что нашёл
  каждый.
- Латентность: +1 вызов LLM на поиск. Для 7b на CPU это секунды; в README
  честно написать.
