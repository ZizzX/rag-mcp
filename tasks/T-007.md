## Goal

Переупорядочивать top-N кандидатов после RRF моделью, которая видит вопрос и
текст чанка вместе (cross-encoder). Обычно это самый заметный прирост точности
на верхних позициях. Включается настройкой, по умолчанию выключен, пока eval не
покажет выигрыш на документах пользователя.

## Understanding

- Интерфейс `Reranker.rerank(query, candidates) -> scores`, провайдеры через
  `RAG_RERANK_PROVIDER`:
  - `none` (по умолчанию);
  - `ollama`: pointwise-оценка релевантности маленькой чат-моделью
    (`RAG_RERANK_MODEL`, например qwen2.5:3b) с промптом «0..10»; без новых
    зависимостей, но медленно: N запросов на поиск, ограничить N=20 и
    параллелить;
  - `api`: Cohere / Voyage / Jina rerank через httpx, один запрос;
  - `local`: `sentence-transformers` + `bge-reranker-v2-m3` как extra
    `rag-mcp[rerank]`, тяжёлая зависимость (torch), ставить только по желанию.
- Кандидатов берём `top_k * candidate_multiplier` из RRF, после реранка
  обрезаем до `top_k`. Поле `matched` сохраняется, добавляется `rerank_score`.
- Решение «включать или нет» принимается по `rag-mcp eval`: hit-rate и MRR до и
  после на одном наборе вопросов. Без набора вопросов задачу не закрывать.
- Для русского корпуса предпочесть многоязычные модели (bge-reranker-v2-m3,
  Cohere rerank-multilingual).
