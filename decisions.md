# Decisions

## D-001 · 2026-10-15 · Координация агентов через pm-доску
- why: несколько агентов в разных ворктри одного репо; доска общая для всех ворктри на этой машине, claim показывает, кто что взял
- rejected: общий markdown-файл в репо (живёт в ветке, конфликты); пересылка текста между сессиями вручную
- tasks: T-001, T-002, T-003, T-004

## D-002 · 2026-10-15 · Локальное хранилище: файлы + numpy вместо встроенного Qdrant
- why: встроенный Qdrant пускает к папке один процесс, а каждая сессия Claude Code запускает свой rag-mcp serve; индекс маленький (~150K, десятки файлов), полный перебор numpy занимает миллисекунды; атомарная замена файлов даёт читателей без блокировки, index.lock только у писателей
- rejected: открывать встроенный Qdrant на каждый вызов и закрывать (длинный ingest блокирует все поиски); глобальная блокировка на чтение и запись; Qdrant в Docker по умолчанию (лишняя зависимость)
- tasks: T-002, T-003

## D-003 · 2026-10-15 · Авто-ingest при старте сервера и инструмент reindex
- why: пользователь не должен помнить про ingest: сервер в фоне индексирует файлы, изменённые с прошлого коммита манифеста, reindex обновляет без перезапуска; пишет через отдельный store, поиск не ждёт
- rejected: только ручной reindex/ingest; слежение за папкой (watch) — лишняя сложность для M1
- tasks: T-003

## D-004 · 2026-10-16 · Подключённые проекты — виртуальный префикс <имя>/ в общем индексе
- why: Хранилище, скоуп, common/, doc_id и needs_ingest уже держатся на source; если подключённая папка отдаёт source = <имя>/<путь>, меняются только обход файлов, реестр projects.json и определение проекта (путь → origin → .git → имя). Индексация на месте по git ls-files, без копий.
- rejected: Симлинк в data/docs: на Windows нужны права, git-фильтр сбоку, метаданные всё равно хранить. Отдельный индекс на проект: переписывание хранилища и слияние индексов для поиска по всем проектам и common/.
- tasks: T-014, T-015, T-016, T-017, T-018, T-019
